## Root Cause Analysis

The test is failing because code in the WebDriver setup is casting an `EventFiringWebDriver` wrapper to the concrete `OpenQA.Selenium.WebDriver` class. `EventFiringWebDriver` wraps an underlying `IWebDriver` and does not extend the concrete `WebDriver` class, so a direct downcast raises a `System.InvalidCastException` at runtime.

The correct approach is to:
1. Depend on the `IWebDriver` interface rather than the concrete `WebDriver` class throughout the framework, **or**
2. Unwrap the underlying driver via `EventFiringWebDriver.WrappedDriver` when a concrete type is strictly required.

## Evidence

```
  to type 'OpenQA.Selenium.WebDriver'.
```

The secondary error — `System.Exception: Unable to DeSelect ShiftCell of EmployeeA Sunday` — is a downstream consequence of the driver not being properly initialised due to the cast failure.

## Suggested Fix

### QA / Test Framework

Replace all usages of the concrete `WebDriver` type in driver-handling code with the `IWebDriver` interface. For example:

```csharp
// ❌ Before – fails when the driver is wrapped by EventFiringWebDriver
WebDriver driver = (WebDriver)DriverFactory.GetDriver();

// ✅ After – works with any IWebDriver implementation
IWebDriver driver = DriverFactory.GetDriver();
```

If a page-object or helper method requires the concrete type for a specific API, unwrap instead of casting blindly:

```csharp
// ✅ Safe unwrap when the concrete type is genuinely needed
if (DriverFactory.GetDriver() is EventFiringWebDriver efDriver)
{
    WebDriver concreteDriver = (WebDriver)efDriver.WrappedDriver;
    // use concreteDriver ...
}
```

## Copilot Investigation Notes

### Type Hierarchy Clarification

`EventFiringWebDriver` (namespace `OpenQA.Selenium.Support.Events`) implements `IWebDriver` but does **not** inherit from the concrete `OpenQA.Selenium.WebDriver` class. Any location in the framework that declares a variable or parameter as `WebDriver` (the concrete class) rather than `IWebDriver` (the interface) will throw `InvalidCastException` when the driver has been wrapped by `EventFiringWebDriver`.

### Common Problem Locations

| Location | Anti-pattern to fix |
|---|---|
| `DriverFactory` / driver initialisation | `return (WebDriver)driver;` → `return driver;` (return type `IWebDriver`) |
| Base test class (`BaseTest` / `TestBase`) | `protected WebDriver Driver` → `protected IWebDriver Driver` |
| Page-object constructors | `public SomePage(WebDriver driver)` → `public SomePage(IWebDriver driver)` |
| Helper/extension methods | Any parameter typed `WebDriver` → retype as `IWebDriver` |

### Why the Secondary Error Occurs

Once the cast exception fires during driver setup the `IWebDriver` reference is never populated, so the subsequent call to deselect a shift cell fails with a null-reference / uninitialised driver error. Fixing the cast will resolve both reported errors.
